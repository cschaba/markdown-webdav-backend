# Effort record: the first session, 2026-09-19

What it took to get from the one-page idea in the first commit to the state of
commit `1ee6b86`: one session with Claude Code (model Fable 5.1), one person at
the keyboard. A snapshot taken at 20:25 that day, not a figure that stays true
— the session went on, and every later session adds its own.

Everything here is measured: time and tokens from the session's transcript with
`tools/session-stats.py`, the rest from git and the files.

## Time

| | |
|---|---|
| Session | 13:57 → 20:25, **6 h 28 min** |
| The model working (a prompt → its last action of that turn) | **2 h 49 min** |
| Waiting for the person (end of a turn → the next prompt) | 3 h 38 min |
| Prompts from the person | 35 |
| Longest turns | 28 min (the MVP), 19, 12.5, 12 and 11 min |

"Waiting" is the person reading, trying things in the browser and deciding. It
is not idle time, and it is where most corrections of course came from.

## Tokens

369 model responses.

| | Tokens |
|---|---|
| Output, generated by the model | **565,134** |
| Input, uncached | 812 |
| Written to the prompt cache | 1,028,265 |
| Read back from the prompt cache | 143,704,818 |
| Total processed | 145,299,029 |

The total is large for one reason. Each of the 358 tool calls (294 shell
commands, 48 file reads, 13 writes and edits) sends the whole conversation
again, and almost all of that is read from the cache, which is billed at a
fraction of the normal input rate. The 565 k output tokens are the actual
product: code, tests, docs, replies and reasoning.

No price is given here. Rates change; the transcript or `/cost` in Claude Code
is the place to look.

## What it produced

| | |
|---|---|
| Go, production | 3,905 lines in 21 files |
| Go, tests | 2,771 lines, 56 test functions |
| JavaScript, CSS, HTML | 1,446 lines |
| Browser and PDF checks (`tools/`) | 677 lines in 5 scripts |
| Docs (README, AGENTS, ARCHITECTURE) | 821 lines |
| Test vault | 40 files |
| Git | 11 commits, 9 feature branches merged; +11,800 lines in 109 files |

The MVP took the first four hours: WebDAV, git versioning, rendering,
backlinks, foldable headings, several vaults, the test vault, Excalidraw, the
graph. The ten features after it — search, its history, task search, link
resolution, heading links, note embeds, PDF export, keyboard support, slides —
took two and a half hours together, because each could lean on the test vault
and the check scripts that existed by then.

About 48 output tokens per line that ended up in the repository. That is high
for plain code generation and is what verification costs: real PDFs read back,
browsers driven with real keys, every rendered link of a real vault compared
before and after a change. Those checks found most of the bugs that the HTML
tests could not see (listed in the commit messages of the features concerned).

## What would have been cheaper

- **One session per feature.** A long session re-reads itself on every tool
  call; by the end each call carried several hundred thousand tokens of
  history. A fresh session starts small. `AGENTS.md` and `ARCHITECTURE.md` are
  written so that one can pick up without this history.
- **Fewer full runs.** The server was restarted about 25 times and whole check
  suites were rerun where only one part had changed.
- **Measuring before estimating.** The search was first announced with an
  estimated speed, then measured four times slower, with a worst case of ten
  seconds. The estimate cost a round of rework that a benchmark up front would
  have saved.

## Reproducing the figures

```sh
tools/session-stats.py ~/.claude/projects/<project>/<session>.jsonl
git diff --shortstat 0a0a97f 1ee6b86
```
